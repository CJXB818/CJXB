JavaScript 的两种定时器

徐奔 · setTimeout 执行一次 · setInterval 反复执行

一、先分清：一次 与 反复

setTimeout(fn, 毫秒)：等一会儿，只执行一次，执行完就结束了。
setInterval(fn, 毫秒)：每隔一段时间就执行一次，不会自己停，必须手动清除。
两者都返回一个数字 id，用 clearTimeout(id) / clearInterval(id) 取消。
// 3 秒后执行一次 const t1 = setTimeout(() => { console.log('3 秒到了'); }, 3000); // 取消（还没到时间才有效） clearTimeout(t1); // 每隔 1 秒执行一次，不停 const t2 = setInterval(() => { console.log('嘀嗒'); }, 1000); // 必须手动清除，否则会一直跑 clearInterval(t2);
对比项 setTimeout setInterval
执行次数 一次 无限次，直到被清除
清除方法 clearTimeout(id) clearInterval(id)
典型场景 提示自动消失、延迟加载、防抖 时钟、倒计时、轮播图、进度条
注意点 页面关闭前能执行到的机会不多 忘记清除会让回调越积越多，页面变卡

二、setTimeout：3 秒后执行一次

点击按钮开始，倒计时结束后回调函数才执行，页面提示变绿。 倒计时进行中再点“提前取消”，可以看到 clearTimeout 把这次执行彻底取消掉。

function start() { log('开始计时'); timeoutId = setTimeout(() => { log('3 秒到，执行回调'); msg.textContent = '✔ 回调已执行'; }, 3000); } function cancel() { clearTimeout(timeoutId); log('已取消，回调不会执行'); }
[等待] 点击“开始”按钮，观察回调在几秒后执行。

四、两个容易踩的坑

坑 1：setInterval 写完之后忘记清除，组件销毁了回调还在跑，久了页面就卡，控制台还会报错说找不到元素。
坑 2：setInterval 的间隔是“最短间隔”，如果回调本身很耗时，实际间隔会被拉长，做倒计时会有误差。 需要精确计时时，用递归的 setTimeout 或者记录开始时间戳自己算。
// 坑 2 的解法：不用 setInterval，用时间戳自己算 const startTime = Date.now(); function tick() { const passed = (Date.now() - startTime) / 1000; // 真实过去了多少秒 render(passed.toFixed(1)); if (passed < 3) { requestAnimationFrame(tick); // 或者 setTimeout(tick, 100) } } tick();

页面上的倒计时就是这么做的：用 setTimeout 定 3 秒后触发回调， 同时另开一个 100ms 的定时器负责刷新界面上的数字，两者互不干扰。
